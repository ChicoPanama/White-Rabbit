## Analysis Task

Analyze the contract for access control vulnerabilities. Focus on:

### 1. Missing Access Controls
- Functions that modify critical state but lack onlyOwner/role checks
- Functions that can transfer funds without authorization
- Initialization functions callable by anyone (missing initializer guard)
- Upgrade functions without proper access restriction

### 2. Broken Access Control
- Incorrect modifier application (check if modifier actually validates)
- tx.origin vs msg.sender confusion
- Role hierarchy issues (lower roles can escalate to higher)
- Missing access checks on delegatecall targets

### 3. Centralization Risks
- Single owner can drain funds or rug-pull
- Admin can modify critical parameters without timelock
- Owner can pause withdrawals indefinitely
- Backdoor functions (hidden admin capabilities)
- Unrestricted minting/burning capabilities

### 4. Proxy & Initialization Issues
- Uninitialized proxy implementations
- Multiple initialization vulnerability
- Storage collision in proxy patterns
- Initializer not protected with `initializer` modifier

### 5. Privilege Escalation
- Can a regular user gain admin privileges through a sequence of calls?
- Are there functions that can change the owner/admin without proper checks?
- Can role-granting functions be called by non-admins?
