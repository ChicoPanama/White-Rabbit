## Analysis Task

Analyze the contract for reentrancy vulnerabilities. Focus on:

### 1. Classic Reentrancy
- State changes AFTER external calls (ETH transfers, token transfers, low-level calls)
- Check the Checks-Effects-Interactions pattern compliance
- Identify all functions that make external calls and verify state is updated BEFORE the call

### 2. Cross-Function Reentrancy
- Can function A's external call re-enter function B which reads stale state?
- Look for shared state variables modified across multiple external-calling functions
- Check if nonReentrant modifier covers all relevant functions

### 3. Cross-Contract Reentrancy
- ERC-777 token callbacks (tokensReceived, tokensToSend)
- ERC-1155 callbacks (onERC1155Received, onERC1155BatchReceived)
- ERC-721 callbacks (onERC721Received)
- Callback patterns in flash loans (IFlashLoanReceiver)

### 4. Read-Only Reentrancy
- Can a view function return stale data during a reentrant call?
- Are external protocols reading this contract's state during callbacks?
- Check for price/balance/share calculations that could be manipulated

### 5. Protection Assessment
- Is ReentrancyGuard (OpenZeppelin) applied to ALL state-changing external-call functions?
- Are there any functions that bypass the reentrancy lock?
- Is the nonReentrant modifier on the correct functions?
