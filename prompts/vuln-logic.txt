## Analysis Task

Analyze the contract for business logic vulnerabilities specific to its protocol type. Focus on:

### 1. Token Accounting Errors
- Fee-on-transfer token handling (does the contract assume transfer amount == received amount?)
- Rebasing token compatibility (does balance change without transfers?)
- Token with non-standard decimals handling
- Missing return value checks on ERC-20 transfers (USDT doesn't return bool)

### 2. State Machine Violations
- Can protocol states be reached in unintended order?
- Are there time-dependent operations that can be front-run?
- Can expired operations still be executed?
- Are there race conditions between competing transactions?

### 3. Economic Logic Flaws
- First depositor / inflation attacks on vault share calculations
- Sandwich attack vectors on slippage-sensitive operations
- MEV extraction opportunities in privileged operations
- Reward distribution calculation errors
- Interest rate model manipulation

### 4. Edge Cases
- Zero amount deposits/withdrawals
- Maximum value inputs (type(uint256).max)
- Empty array or zero-length inputs
- Self-referential operations (token A == token B in swap)
- Dust amount accumulation

### 5. Protocol-Specific Issues
For the identified protocol type, check:
- **DEX/AMM:** Slippage bypass, LP token manipulation, swap path exploitation
- **Lending:** Liquidation manipulation, bad debt creation, interest rate exploitation
- **Staking:** Reward draining, stake/unstake timing attacks, withdrawal delay bypass
- **Vault:** Share price manipulation, strategy loss socialization, withdrawal queue issues
- **Bridge:** Message replay, double-spend, relayer manipulation
