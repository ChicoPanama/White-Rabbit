## Analysis Task

Analyze the contract for arithmetic vulnerabilities. Focus on:

### 1. Integer Overflow/Underflow
- For Solidity < 0.8.0: Check ALL arithmetic operations for missing SafeMath
- For Solidity >= 0.8.0: Focus ONLY on `unchecked` blocks and inline assembly arithmetic
- Check for implicit type conversions that lose precision (uint256 -> uint128, etc.)
- Look for multiplication before division that could overflow intermediate values

### 2. Precision Loss
- Division before multiplication patterns
- Rounding errors in token amount calculations
- Fee calculations that round to zero for small amounts
- Price calculations with insufficient decimal handling

### 3. Type Casting Issues
- Unsafe downcasting (uint256 to uint128/uint64/uint32/uint8)
- Signed/unsigned conversion issues
- Truncation in packed storage operations

### 4. Economic Exploitability
- Can arithmetic errors be triggered by normal user actions?
- What is the maximum extractable value from the arithmetic bug?
- Can the error be amplified via flash loans or repeated calls?
